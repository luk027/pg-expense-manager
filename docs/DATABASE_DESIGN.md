# PG Expense Manager — Database Design

## Overview

- **Engine:** PostgreSQL (Neon serverless)
- **ORM:** Drizzle ORM
- **Money:** All monetary values stored as **integer paise** (bigint)
- **Soft Deletes:** `deleted_at` timestamp column on mutable tables
- **Timestamps:** All tables include `created_at` and `updated_at`
- **IDs:** UUIDs (generated by the database)

## Key Constraints & Rules

1. **One active room per user** — Enforced by unique constraint on room_members(user_id) where status = 'active'.
2. **One admin per room** — Enforced by application logic during admin transfer.
3. **Full payment only** — Application validates payment.amount_paise = settlement_member_shares.amount_owed_paise.
4. **Idempotency** — Unique constraints on idempotency_key columns (payments, water_deliveries).
5. **No future water entries** — Application validates delivery_date ≤ current IST date.
6. **Soft deletes** — All queries include `WHERE deleted_at IS NULL` by default via Drizzle helper.
7. **Money precision** — All amounts are bigint paise. Sum of shares must always equal the total.
8. **Timezone** — All timestamps stored as timestamptz. Application logic uses IST (Asia/Kolkata).

## Indexes

- `rooms`: (admin_id), (collector_id), (status)
- `room_members`: (room_id, status), (user_id, status)
- `expenses`: (room_id, expense_period), (room_id, settlement_period), (room_id, deleted_at)
- `expense_shares`: (expense_id), (user_id)
- `settlements`: (room_id, period)
- `settlement_member_shares`: (settlement_id, user_id)
- `payments`: (room_id, settlement_id), (payer_user_id), (status)
- `water_deliveries`: (room_id, expense_period), (room_id, delivery_date)
- `activity_log`: (room_id, created_at DESC), (entity_type, entity_id)
